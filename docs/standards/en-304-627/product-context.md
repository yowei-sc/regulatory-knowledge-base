# EN 304 627 產品情境與評估邊界

## 為什麼先做產品情境

相同名稱的網通產品可能有不同的管理介面、雲端依賴、更新機制與部署信任邊界。若未先建立產品情境，測試結果可能只代表實驗室中的局部設定，無法對應實際投放市場的版本。

## 最小產品資料集

### 產品與版本

- 型號、硬體 revision、韌體與軟體版本。
- 出廠設定、區域版本及可選功能。
- 支援期間與更新政策。

### 介面與資料流

- WAN、LAN、無線、管理與維護介面。
- 本機與遠端管理路徑。
- 身分驗證、權限、金鑰與憑證邊界。
- 雲端服務、行動應用程式及第三方相依元件。

### 部署與信任邊界

- 家用、企業或電信網路等預期環境。
- 管理者、一般使用者、維護人員與服務供應商角色。
- 預設開放服務、網路分區與實體存取假設。

## 從要求到證據

每個要求至少建立下列追溯鏈：

```text
適用要求 → 產品設計控制 → 測試方法 → 原始結果 → 判定 → 未解風險
```

測試報告應能重現環境、輸入、操作步驟與版本。只有「Pass」或掃描器摘要，通常不足以說明測試範圍及判定依據。

## 結果判讀

| 觀察 | 可以支持 | 不能直接支持 |
|---|---|---|
| 特定版本通過定義清楚的測試 | 該版本在該環境符合測試判準 | 所有版本、設定與部署都符合 |
| 介面未偵測到弱服務 | 本次範圍未觀察到該服務 | 產品不存在其他攻擊面 |
| 文件描述安全更新流程 | 已設計流程與責任 | 實際更新一定安全且持續執行 |
| 掃描器未發現已知漏洞 | 指定資料庫與掃描條件下未命中 | 產品沒有漏洞 |

## 尚待確認事項

EN 304 627 尚處核准階段。正式使用前需重新確認最終版本、發布狀態、內容差異，以及是否被歐盟官方公報引用為 CRA 調和標準。
