# O-RAN 安全測試概覽

## 測試分類

O-RAN 安全測試可用下列層次整理。這是本站為理解測試證據所做的高階分類，不取代規格中的正式測試案例與編號。

### 協定與安全通道

檢查安全協定、憑證、金鑰、演算法、身分驗證與失敗處理。測試不只確認「有加密」，也要確認雙方身分、協定狀態、降級行為與信任鏈。

### 介面與存取控制

確認不同 O-RAN 介面的身分、角色、授權及資料邊界。測試需要明確區分未認證、已認證但未授權，以及授權範圍錯誤三種失敗。

### 平台與系統強韌性

觀察服務暴露、預設設定、弱密碼、防暴力嘗試、輸入處理、資源耗盡、日誌與漏洞管理。自動化掃描只能提供線索，仍需人工確認版本、可達性與實際影響。

### 軟體與供應鏈

評估軟體元件清單、套件來源、完整性、簽章、更新與已知漏洞處理。SBOM 能建立元件可視性，但不等於已完成風險分析或修補。

## 最小可重現測試紀錄

- 測試目標、介面、元件與版本。
- 前置條件、帳號角色、憑證與網路拓樸。
- 工具版本、完整命令、輸入與時間。
- 封包、日誌、系統狀態與原始回應。
- 成功／失敗／不適用的判定準則。
- 發現事項的影響、限制、重測步驟與修補證據。

## 失敗定位

測試失敗時，先判斷是哪一層：

```text
連線與路由
  ↓
TLS／安全通道
  ↓
認證
  ↓
授權
  ↓
協定與資料格式
  ↓
應用邏輯
  ↓
平台權限與資源
```

一次只改一個變因並保留 baseline，才能知道是產品控制生效、測試環境錯誤，還是前置條件不成立。

## 結果判讀

- **掃描器沒有告警：**只代表目前資料庫、探測範圍與條件下未命中，不代表沒有漏洞。
- **連線被拒絕：**可能是服務未啟動、路由、防火牆或存取控制；尚不能直接判定安全控制有效。
- **認證成功但操作失敗：**需區分授權拒絕、資料格式錯誤與應用邏輯錯誤。
- **修補後測試通過：**仍需確認相同版本、設定與部署條件，並保留回歸測試證據。
