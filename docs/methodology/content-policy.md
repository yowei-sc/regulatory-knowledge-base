# 內容與引用政策

## 查證流程

每篇文章依序確認：文件身分、官方狀態、版本或法規編號、適用範圍、查證日期及官方連結。無法由第一手來源確認的內容，標為作者理解或尚待確認，不補造結論。

## 摘要與引用

- 以自己的文字說明制度與技術概念。
- 不大量逐字翻譯法規、商業標準或測試案例。
- 必要的短引文緊鄰標示來源。
- 技術規格中的 `shall`、`should`、`may` 保留不同強度。
- 文章不能用「保證合規」或「通過認證」取代正式評估證據。

## 私有資料

私有簡報、內部整理與客戶資料只能用來理解背景或尋找公開來源。公開頁面不得包含原檔、公司或客戶名稱、未公開產品結論、本機路徑、帳號、金鑰與內部網址。

## 版本與狀態

每篇文章以 Front Matter 記錄 `version`、`status` 與 `last_verified`。只要文件版本、核准階段或法律時程改變，就要重新查證並更新頁面，不以舊文章的描述取代現行官方紀錄。

## 發現錯誤時

修正內容時保留 Git 紀錄，並同步檢查導覽、內部連結及其他引用同一結論的頁面。若錯誤會改變適用性或法規義務，應在相關頁面明確說明修正範圍。
