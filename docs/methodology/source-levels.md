# 資料來源分級

來源分級不是在判斷文件「有沒有用」，而是在限制它可以支持的結論強度。

| 等級 | 來源類型 | 適合支持的內容 | 不應單獨支持的內容 |
|---|---|---|---|
| 第一級 | EUR-Lex、歐盟官方公報、主管機關官方網站 | 法律義務、生效與適用日期、正式條文 | 技術實作細節或產品測試結論 |
| 第二級 | ETSI、O-RAN ALLIANCE 等官方組織 | 標準版本、文件狀態、技術要求與規格定位 | 未經法律文件建立的強制義務 |
| 第三級 | RFC、官方技術指南、公開測試文件 | 協定行為、測試方法、技術背景 | 法律適用性或產品合規結論 |
| 第四級 | 公司簡報、顧問說明、內部整理 | 協助理解、建立查證線索 | 公開文章的唯一證據或正式結論 |

## 使用原則

1. 涉及法律義務時，回到第一級來源。
2. 涉及標準版本與狀態時，查第二級來源的現行紀錄。
3. 第三級來源用於解釋技術，不把建議寫成法律要求。
4. 第四級來源不公開原始內容，也不公開公司、客戶或未公開產品資訊。
5. 不同來源矛盾時，保留差異並標示查證日期，不任選一個答案。

## 快速判斷

!!! question "這段話能不能寫成『必須』？"
    先問：它是法規條文、標準中的 `shall`，還是說明文件中的建議？只有來源、適用範圍與前置條件都確認後，才能決定使用「必須」「應」或「可以」。
